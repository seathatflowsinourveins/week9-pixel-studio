TELL YOUR GROUP

Five ideas. In this order.

Use these as speaking notes. Add what your group actually sees.

  1. Load. We wait for the image, resize it, then read its pixels.
  2. Time. A minute of elapsed animation becomes 0 to 1. Check the original’s clock note below.
  3. Sample. A grid chooses pixels. Each pixel has RGBA numbers.
  4. Translate. Average RGB controls size. Time and brightness control hue.
  5. Draw. Many circles rebuild the image. When progress reaches 1, it holds.

Clock note · a correction for a separate revision

The original saves startTime during setup. In p5 2.3.4, the clock resets again before draw begins. The saved setup reading can therefore make the first progress values negative and delay the intended start. min only caps the upper end.

For your own revision: remove the assignment to startTime in setup. At the beginning of draw, before calculating progress, add:

if (startTime === undefined) {
  startTime = millis();
}

This saves the first draw reading once. Our model uses chosen elapsed seconds from 0 to 60; it illustrates that intended timeline, rather than this clock-reset side effect. With a very slow load the original’s grid spacing can become zero or negative and stall its loops; this is a source-review finding, not a stall observed here. The original remains unchanged.
